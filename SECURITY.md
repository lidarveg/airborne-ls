# Security Policy

## Supported Versions

This project is maintained on a best-effort basis.

| Version | Supported     |
|---------|---------------|
| Latest  | ✅ Yes        |
| Older releases | ❌ No  |

Only the most recent version will receive security updates.

---

## Reporting a Vulnerability

If you discover a security issue, please report it responsibly.

- **Email:** robert.denham@uq.edu.au
- **Subject:** Security vulnerability in airborne-ls

Please include:
- A clear description of the issue
- Steps to reproduce (if applicable)
- Potential impact
- Any suggested fixes (optional)

---

## Response Expectations

As this is a small project maintained with limited resources:

- We aim to **acknowledge reports within 5–10 working days**
- Fix timelines will depend on severity and available time
- Critical issues will be prioritised where possible

---

## Disclosure Policy

We follow a **coordinated disclosure approach**:

- Please do **not publicly disclose** the vulnerability before it is addressed
- We will notify you when a fix is available
- Once resolved, we may publish a brief security advisory

---

## Scope

This policy applies to:

- The source code in this repository
- Official releases of this project

Out of scope:
- Third-party dependencies (please report issues to their maintainers)
- Misconfigurations in downstream usage

---

## Security Practices

This project follows lightweight security practices appropriate for small open-source software:

- Dependency monitoring and updates
- Basic static analysis via CI
- No intentional inclusion of secrets or credentials
- Minimal dependency footprint where possible

---

## Disclaimer

This is a small, best-effort open-source project. While reasonable care is taken to ensure security, **no guarantees are made regarding the absence of vulnerabilities**.

Users are responsible for assessing the suitability and security of this software for their use case.
